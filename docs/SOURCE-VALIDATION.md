# Source validation boundary

The hosted Windows gate parses all four owned PowerShell scripts and rejects unreviewed commands, types, methods and function definitions before executing them. Each behavior scenario runs in a fresh child PowerShell process with USERPROFILE, LOCALAPPDATA and APPDATA redirected to a disposable fixture. File operations reject paths outside the fixture; copying source scripts permits only the two reviewed files.

Registry operations, COM shortcut creation, all scheduled-task operations, powercfg, whoami and process launches resolve to test functions. No registry provider, COM activation, scheduler, power change, user lookup or shell-refresh process is invoked. Direct escape attempts are negative tests. The real wallpaper DllImport definition is hash checked and never compiled; a pure managed stand-in records its calls. The Screen type is a precompiled managed fixture with fixed bounds, and the child fails before execution if a real Screen type is already loaded.

Offscreen System.Drawing processes generated fixture images only. Tests inspect the actual output pixels, contained aspect ratio, centered geometry, state progression, duplicate sources, exclusions and image errors. They do not capture a screen, read personal photographs or activate a desktop wallpaper. Installer tests preserve unrelated fixture files and noncanonical shortcut bytes, check all fourteen app shortcuts and task contracts, and rerun installation. Shell tests exercise critical readback failures; verification tests read actual fixture JSON and mocked task status.

The nested photo-filter regression failed against the original source because the inner pipeline changed the meaning of `$_`. Capturing the outer photo object fixes only that exclusion behavior. The original script encoding, parameters, scheduler contracts and desktop settings remain unchanged.

The full Windows lane runs without the optional portable-subset flag. The portable local subset is additional evidence and does not substitute for Windows behavior/image tests. Both complete Git history and the effective tree are scanned with checksum-verified Gitleaks using explicit embedded-default configuration and inline-allow suppression disabled. Candidate configuration/environment overrides cannot suppress findings. Any source-root .gitleaksignore, including a symlink or dangling symlink, is rejected before scanning; this is an authority refusal, not a claim of secret detection. Generated private-key, inline-token, configuration/environment and ignore-path controls verify the strict scanner boundary without storing credential values in source.

This is ordinary review-protected GitHub CI. It does not certify user desktops, administrator privileges, actual hardware, real device access, provider effects, runtime activation or production deployment. Existing owner CI work and the feature default branch remain unchanged.
